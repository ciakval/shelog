<objective>
Turn the tracer's fixed-interval loop into a collector that can run unattended for weeks and can be trusted with the rate limit:
- deadline-based jittered scheduling
- capped exponential backoff, 429/Retry-After handling, and a distinct auth-rejected state
- a poll_log row for every attempt, including our own bugs
- a single-instance lock and SIGTERM-clean shutdown

Then prove the urllib transport and the classifier against real sockets and every envelope category.

Purpose: COLL-01/02/05. A collector that hammers a rejected key, bursts after an outage, or dies silently on an unexpected exception loses data or gets the account throttled.
Output: hardened transport/client, the full poll loop in poller.py, lock.py, meta helpers, and offline tests that run a simulated 6-hour window in milliseconds.
</objective>

1. Constants and `next_delay`:
   - CAP_S, MIN_GAP_S, AUTH_FLOOR_S, AUTH_CONFIRMATIONS, STARTUP_FAIL_SLEEP_S.
   - ok: interval × rng.uniform(0.9, 1.1).
   - Failure: base = min(CAP_S, interval × 2^(n-1)), then delay = base/2 + rng.uniform(0, base/2) (equal jitter).
   - rate_limited with retry_after: max(delay, retry_after).
   - auth: max(delay, AUTH_FLOOR_S).
   - Floor the result at MIN_GAP_S.
   - Jitter uses the injected `random.Random`. Add `# noqa: S311` with a reason if ruff flags it: this is not crypto.
2. `run(poller, stop, clock, rng)`:
   - Scheduling uses monotonic deadlines.
     - After ok: next deadline = previous deadline + next_delay(...). If that falls behind now, it becomes now + MIN_GAP_S. Never catch up with bursts after an outage.
     - After a failure: next deadline = now + next_delay(...).
   - The consecutive-failure counter resets on ok.
   - Wait with clock.wait(stop, remaining), so SIGTERM ends the wait immediately.
   - Every exception escaping step is caught at the loop boundary (Interrupted means stop):
     - Write PollRecord(ok=0, error='internal') through store.write_cycle in its own try/except.
     - Log ERROR with the exception TYPE NAME only, never str(exc) (D-05).
     - Count it as a failure for backoff and continue.
   - Auth state machine:
     - A counter of consecutive auth outcomes. When it reaches AUTH_CONFIRMATIONS (2: a throttle may masquerade as 401, Pitfall 3), go to state 'rejected'. Log ERROR "Shelly Cloud rejected the auth key; retrying every 300 s" once per transition and persist meta shelly_auth='rejected' plus shelly_auth_since.
     - The first ok afterwards sets 'ok', logs INFO "Shelly Cloud accepted the auth key again", and persists the change.
     - On startup, if meta is absent, write 'ok' after the first ok.
   - Never-inserted watchdog: count per device the ok cycles in which it was present while load_last_states has no row for it. At 10, log one WARNING by device NAME.
   - bad_response: log WARNING "unexpected response body (truncated)" plus `outcome.body_excerpt` (added to Outcome in Task 1). Nothing from the body goes to the DB.
3. `main` keeps the frozen positional signature and adds keyword-only `clock=None, send=None, rng=None` for tests.

   - An OSError while creating the lock file, a DB open/migrate failure, or SchemaTooNew:
     - in loop mode: log ERROR with the type name, clock.wait(stop, STARTUP_FAIL_SLEEP_S), return 1. This avoids a hot restart loop under `restart: unless-stopped` that would burn the account's rate limit.
     - with once: return 1 immediately.
   - SIGTERM/SIGINT handlers only set the Event. Close the DB on exit and return 0 after a stop.
4. `lock.py`: create the parent directory, open in "a+", `fcntl.flock(fd, LOCK_EX | LOCK_NB)`, map BlockingIOError to AlreadyRunning. The caller keeps the handle for the process lifetime.
5. `db.py`: set_meta is an UPSERT inside its own BEGIN IMMEDIATE / COMMIT, with ROLLBACK on error. get_meta returns the value or None.
