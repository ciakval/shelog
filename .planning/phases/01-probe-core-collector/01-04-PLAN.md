<objective>
Make leaking the Shelly auth key structurally hard and verifiable, and make the device inventory impossible to misconfigure silently:
- strict validation of settings and devices.toml
- documented example files
- a redacting log formatter that scrubs the key from every line, including tracebacks
- `shelog check`, a leak scanner that runs against the real key without anyone reading the secrets file

Purpose: COLL-07/08. The repo is public and the key controls the owner's devices; a typo in devices.toml must fail loudly instead of silently dropping a sensor.
Output: strict config.py, logging_setup.py, check.py, `shelog check`, devices.example.toml, .env.example, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied config (env, secrets file, devices.toml) → app | Misconfiguration or crafted host values enter here |
| app → logs/stdout/stderr (later container logs) | Any text emitted may end up in shared logs |
| app → local files (DB, WAL, probe output) | Persistent artefacts that could be copied or backed up |
| public git repo | Example files only; real inventory and secrets stay server-side |
