1. `src/shelog/shelly/parse.py` (D-07, D-08):
   - `parse_cloud_ts`: accept only a str, return int of `datetime.fromisoformat(value + "+00:00")` as a timestamp, or None. This is DTZ-clean UTC.
   - A private numeric guard returns float for int or float values, excluding bool and non-finite values. Anything else becomes None, never 0.
   - `parse_device` dispatches on model:
     - `ht_gen1`: `tmp.tC` only when `tmp.is_valid is True`; `hum.value` only when `hum.is_valid is True`; `bat.value`.
     - `ht_gen3`: `temperature:0.tC`, `humidity:0.rh`, `devicepower:0.battery.percent`.
     - `flood_gen1`: `tmp.tC`; `flood` must be a bool and becomes int 0 or 1; `bat.value`; rh None.
   - Structure check: the block must be a dict holding the model's anchor key (`tmp`, `temperature:0`, or `flood`), else ParseReject 'shape'.
   - `_updated` missing or unparseable gives ParseReject 'no_ts'. Plan 01-03 refines these branches.
   - ts_source is 'cloud'. raw is `json.dumps(block, separators=(",", ":"))`.
   - Never use `tmp.value` (it follows the configured units) or any device clock for ts.

2. `src/shelog/migrations/0001_init.sql` and `src/shelog/db.py` (D-12):
   - Copy the schema verbatim from research lines 390-451, comments included: six STRICT tables, WITHOUT ROWID where shown, and the poll_log_kind_ts index.
   - `connect_rw`: create the parent directory with mode 0o700, `sqlite3.connect(path, isolation_level=None, timeout=5)`, then run the WAL, synchronous NORMAL, busy_timeout 5000 and foreign_keys ON pragmas outside any transaction.
   - `migrate`:
     - Enumerate `NNNN_*.sql` under `importlib.resources.files("shelog") / "migrations"`, in order.
     - For each migration above the current user_version, run executescript of "BEGIN IMMEDIATE;" + sql + "PRAGMA user_version = N;" + "COMMIT;".
     - On any exception, ROLLBACK if `con.in_transaction`, then re-raise.
     - Raise SchemaTooNew when user_version exceeds the highest known migration. Return the final version.
   - Use only SQLite 3.46 features.

3. `src/shelog/store.py` (D-12, D-13): follow research Pattern 3 and the write_cycle example.
   - `decide` for ts_source 'cloud':
     - not plausible: IMPLAUSIBLE
     - last is None or ts > last.ts: INSERT with Decision.ts = report.ts
     - equal: UNCHANGED
     - lower: REGRESSED
   - `load_last_states`: latest row per device where source = 'poll'.
   - `write_cycle`:
     - One `BEGIN IMMEDIATE` transaction. Insert the poll_log row first, then each reading with `ON CONFLICT DO NOTHING`.
     - Insert raw_status only when that reading's rowcount is 1. A rowcount of 0 counts as unchanged and is never silent.
     - Finish with an UPDATE of that poll_log row's n_new and n_unchanged to the real counts, then COMMIT.
     - On any exception, ROLLBACK and re-raise. Return the actual n_new.
   - Use parameterized SQL only.

4. `src/shelog/poller.py`:
   - `Poller` loads `last_states` once at construction.
   - `step(stop)`:
     - Set `now = int(clock.time())` and call `client.fetch_all_status(stop)`.
     - On ok, handle each configured device present in `outcome.devices` by id: call parse_device inside its own try/except, so one bad block never aborts the cycle. An exception or ParseReject adds 1 to n_rejected and logs a WARNING with the device NAME and reason only (for an exception, its type name only). Then call decide.
     - INSERT builds a ReadingRow from Decision.ts. UNCHANGED adds to n_unchanged. REGRESSED and IMPLAUSIBLE add to n_rejected. Every report's `field_rejects` also adds to n_rejected.
     - n_devices is the number of configured ids present. When none are present, turn the outcome into no_devices (ok=0).
     - Call write_cycle, then update last_states only for actually inserted rows. Log each inserted report's `warnings` with the device name.
     - Log one INFO line per cycle with category, n_new, n_unchanged, n_rejected and latency, and no ids, host or key.
     - A failed outcome writes `PollRecord(ok=0, error=category, http_status, retry_after_s rounded to int, latency_ms)` with no readings.
     - Return CycleResult.
   - `main(settings, devices, *, once)`:
     - Run connect_rw and migrate, and build SystemClock, RateGuard and ShellyClient.
     - Install SIGTERM and SIGINT handlers that only set a `threading.Event`.
     - With once: a single step, returning 0 if ok, else 1.
     - Otherwise: loop step then `clock.wait(stop, settings.poll_interval_s)` until stop is set, and return 0.
     - Plan 01-04 replaces this loop body with deadlines, jitter, backoff and the lock, keeping both signatures.

5. `src/shelog/cli.py`: add the subcommand `poll` with `--once`, dispatching to `poller.main(settings, devices, once=args.once)`. Keep `probe` and the ConfigError handling unchanged.

6. Run the live slice last: `scripts/live.sh poll --once` (one request).
